# COMANDO WhatsApp Bot

## البوت اللي بيبعت كل إشعار/إعلان من المنصة تلقائيًا لجروبك على WhatsApp

يراقب البوت جدول `announcements` (الإعلانات المنشورة) وجدول `notifications` (الإشعارات العامة)
في Supabase بتاع منصة COMANDO، ويرسل أي منشور جديد إلى مجموعة WhatsApp واحدة أو عدة مجموعات
مرتبطة بحسابك الشخصي عبر QR Code.

> ⚠ هذا البوت **غير رسمي** (`whatsapp-web.js`) يعمل بنفس حسابك الشخصي. اقرأ قسم «هل هذا البوت غير رسمي؟» قبل الاستخدام.
> البديل الرسمي هو WhatsApp Business Cloud API.

---

## المتطلبات

- جهاز Windows **يعمل** (البوت بيشتغل طالما الجهاز شغال + فيه جلسة مستخدم + الإنترنت متصل).
- Node.js 18+ (مثبت عندك — v24).
- مفتاح `service_role` من Supabase (قراءة فقط — **لا تنشره أبدًا**).
- حساب WhatsApp نشط + المجموعة تكون أنت عضو فيها (يفضل أدمن).

## الخطوة 4 — ربط WhatsApp

```powershell
.\scripts\pair.ps1
```

أو:

```powershell
npm run pair
```

1. هيظهر QR Code في الطرفية.
2. على موبايلك: WhatsApp → ⋮ (أو الإعدادات) → **الأجهزة المرتبطة** → **ربط جهاز** → امسح الـ QR.
3. بعد المسح → الجلسة تتحفظ في مجلد `.wwebjs_auth/` تلقائيًا.
4. البوت يخرج لوحده بعد الربط.

**ملاحظة:** مسح الـ QR **مرة واحدة فقط** — الجلسة محفوظة دائمًا على القرص.
لو عايز تغير الرقم المرتبط: احذف مجلد `.wwebjs_auth/` وشغّل `pair.ps1` تاني.

**ملاحظة تقنية:** WhatsApp Web لا يعمل مع المتصفحات الخفية (headless)، فالبوت يشغّل Chromium **صغير خارج الشاشة** (200×200 على مسافة -2000 بكسل) — لن تراه عمليًا، لكنه لازم للربط.

## الخطوة 5 — الانضمام للجروب وتحديده

### الطريقة أ (لو الجروب برابط دعوة وما تظهرش في حسابك)

> ملاحظة: الانضمام البرمجي بيعتمد على دوال داخلية في WhatsApp Web وأحيانًا تتعطل (ظهرت معطلة لحظة كتابة الدليل). المجرب والأضمن:**افتح رابط الدعوة من الموبايل واضغط «انضمام»** — ثواني — وبعدين كمل بالطريقة ب تحت.

حط رابط الدعوة في `GROUP_INVITE_CODE` داخل `.env` (الرابط كامل أو الكود بس)، ثم:

```powershell
.\scripts\join-group.ps1
```

لو نجح: البوت هينضم للجروب ويكتب `TARGET_GROUP_ID` في `.env` تلقائيًا.
لو فشل (رسالة فيها `joinGroupViaInvite`): الانضمام غير متاح حاليًا — افتح الرابط من الموبايل واضغط «انضمام» ثم استخدم الطريقة ب.

### الطريقة ب (لو الجروب متاح في حسابك بالفعل)

```powershell
.\scripts\list-groups.ps1
```

أو `npm run list-groups` — هيطبع كل المجموعات في حسابك مع معرّف كل واحدة (`120363001234@g.us`).

انسخ الـ **اسم** الصقه في `TARGET_GROUP_NAME` داخل `.env` — **أو** انسخ الـ **معرّف** وحطه في `TARGET_GROUP_ID` (الأدق، ولا يتغير لو غيرت اسم الجروب).

لو عايز تبعت لأكثر من جروب: استخدم `TARGET_GROUP_NAMES=جروب الشعبة,جروب المتابعة` (أسماء مفصولة بفواصل) — كلهم يستقبلوا كل رسالة.

## الخطوة 8 — كيف يشتغل؟

1. كل `POLL_INTERVAL_SECONDS` ثانية (افتراضي ٢٠)، البوت يسأل Supabase:
   - `announcements.is_published = true`
   - `notifications.is_global = true`
2. لكل منشور جديد:
   - يتأكد إن الـ ID مش موجود في `sent.json` — لو موجود: يتخطاه.
   - لو جديد: يرسله ويسجله في `sent.json`.
   - لو الإعلان فيه `link_url` يشير لملف (PDF/صورة/DOCX/PPT/ZIP…) مع `SEND_MEDIA=true` → يُرسل **الملف نفسه** على WhatsApp مع الكابشن.
   - لو ما طلع أي جروب مطابق → يحاول تاني في الدورة الجاية (مع فاصل تصاعدي).
3. ترتيب الإرسال: الأقدم أولاً (حسب `created_at`).

### أول تشغيل على الإطلاق (سلوك التشغيل الأول)

لو `sent.json` **مش موجود** (أول مرة البوت يشتغل):
- بـ `SEND_ON_FIRST_RUN=false` (الافتراضي): البوت يسجل كل الإعلانات/الإشعارات الموجودة حاليًا كـ «مُرسلة» ولا يبعت أي رسائل قديمة — ويبعت الجديدة بس من لحظة التشغيل.
- بـ `SEND_ON_FIRST_RUN=true`: يبعت كل الموجود الحالي للجروب (مفيد لو الجروب جديد وعايزه يشوف المحتوى التاريخي).

## ضمانات الموثوقية

| الموقف | التعامل |
|--------|---------|
| تكرار نفس الإعلان | `sent.json` يحفظ آخر 2000 ID — الإعلان بيتبعت مرة واحدة مهما تكررت الدورات |

## هل هذا البوت غير رسمي؟

**نعم.** يعتمد على `whatsapp-web.js` — أتمتة غير رسمية لواجهة WhatsApp Web.

### القيود والمخاطر

- WhatsApp تملك حق حظر أو تقييد أي حساب يخالف الشروط — الخطر قائم على **حسابك الشخصي**.
- لا تضمن WhatsApp استقرار الواجهة — تحديث غير معلن من WhatsApp ممكن يكسر المكتبة (تحديث `npm update whatsapp-web.js` ممكن يصلحها).
- **البديل الرسمي:** WhatsApp Business Cloud API (https://developers.facebook.com/docs/whatsapp/cloud-api) — لكنه يتطلب حساب Meta Business + رقم هاتف معتمد + رسوم لكل رسالة + مراجعة. لو مشروعك يكبر ويعتمد على الإشعارات، الانتقال للـ API الرسمي هو القرار الصحيح.

### نصائح عملية

- رقم هاتفك **لا يُخزَّن في أي ملف** — البوت يرتبط بمسح QR فقط، والجلسة تتسجل في `.wwebjs_auth/`.
- رابط دعوة الجروب حساس أيضًا (أي حد معاه ينضم) — حطه في `.env` فقط (متجاهَل من Git)، مش في الكود ولا في README.
- استخدم الرقم للإشعارات فقط — **لا** رسائل تجارية جماعية ولا سبام تسويقي.
- لا تشارك مجلد `.wwebjs_auth/` مع أي شخص (هو جلسة كاملة تعادل كلمة مرورك).
- الرسائل تُصاغ بصيغة واضحة احترافية — لو عايز تعدل النص، عدّل `src/format.js` (الملف الوحيد المخصص للصياغة).

## الأسئلة الشائعة

**س: هل أحتاج حساب Meta Business؟**
لا — `whatsapp-web.js` لا يحتاج Meta Business. الحساب الرسمي فقط يحتاجه.

**س: هل الـ service_role key آمن في .env؟**
آمن محليًا لأنه متجاهَل من Git، لكن أي شخص يقرأ الجهاز يشوفه. لا ترفع `.env` ولا تنسخه في مكان عام. لو شكيت إنه اتسرب: Supabase Dashboard → Settings → API → Reset service_role key (وهيتغير عندك في .env فقط).

**س: البوت بيشتغل لو الجهاز قفل؟**
لا. لازم الجهاز صاحي + جلسة مستخدم مفتوحة + إنترنت. لو عايز تشغّله يشتغل بعد تشغيل الويندوز: `shell:startup` → حط shortcut يشغّل `start.ps1`.

**س: أقدر أتابع الحالة من برّه؟**
`.\scripts\status.ps1` على نفس الجهاز، أو راجع `logs/`. لا توجد لوحة ويب — مقصود، تقليل نقاط الفشل.

**س: لو عايز تعيد إرسال كل حاجة من الأول؟**
```powershell
del sent.json
.\scripts\start.ps1
```
(هيبعت الموجود الحالي كله — لأنه بقى "كل شيء جديد" بالنسبة لسجل فاضي).

## الاستضافة على Render / Railway (اختياري — لتشغيل ٢٤/٧ بدون جهازك)

البوت ممكن يشتغل على PaaS container (Docker) بدل جهازك. **مهم تعرف:**

- مش أي استضافة هتنفع — لازم **عملية دايمًا شغالة** + **ديسك دائم** (Render: Background Worker + Disk؛ Railway: Volume).
- **Render free / Railway free ما ينفعوش** — الخدمات اللي بتنام بتكسر البوت. الاستخدام العملي يتطلب خطة مدفوعة (~٥-٧$).
- الجلسة بتتحفظ على الديسك الدائم → مسح QR مرة واحدة بس. أول مرة البوت يشتغل على الاستضافة، هيطبع QR في الـ Logs — امسحه من هناك (WhatsApp → الأجهزة المرتبطة).
- `.env` **مش بيترفع** — كل إعدادات البيئة هتكتبها في لوحة الاستضافة.

### Render (Background Worker)

1. New → **Background Worker** → اختار الريبو بتاعك + Root Directory: `whatsapp-bot` + Environment: **Docker**.
2. أضف **Disk** (1GB مثلاً) mounted at `/data`.
3. متغيرات البيئة في اللوحة:
   ```
   PLATFORM_URL=https://comando-files.vercel.app
   SUPABASE_URL=https://bmqqacvgtevogcuqfryq.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=<المفتاح السري>
   TARGET_GROUP_ID=120363412338773097@g.us
   GROUP_INVITE_CODE=<رابط الدعوة — اختياري>
   AUTH_DIR=/data/.wwebjs_auth
   SENT_STORE_PATH=/data/sent.json
   LOG_DIR=/data/logs
   SEND_ON_FIRST_RUN=false
   POLL_INTERVAL_SECONDS=20
   ```
4. Deploy → افتح **Logs** → امسح QR من موبايلك لما يظهر → الجلسة تتحفظ في `/data/.wwebjs_auth` → ما تمسحش تاني.

### Railway

1. New Project → **Deploy from GitHub repo** → نفس الريبو → Root Directory: `whatsapp-bot` (هيكتشف الـ Dockerfile).
2. أضف **Volume** mounted at `/data`.
3. نفس متغيرات البيئة فوق → Deploy → امسح QR من الـ Logs.

### أمان
- المفتاح `SUPABASE_SERVICE_ROLE_KEY` هيتحط متغير بيئة على اللوحة فقط — مش هيتتبع في git.
- صاحب الاستضافة (Render/Railway) نظريًا يقدر يشوف الملفات على الديسك — لو ده مش مقبول عندك، VPS خاص أو جهازك أفضل.
- لو عايز تفضل على جهازك بدل الاستضافة: كمل زي ما انت شغال (`start.ps1`) وخلاص.
